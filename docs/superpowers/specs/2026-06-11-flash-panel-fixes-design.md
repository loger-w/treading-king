# 閃電下單修正 + 庫存資料鏈修復 — 設計(2026-06-11)

PR #22(feat/capital-order-panel-v2)實測後的修正批次。範圍:閃電面板點擊語意改版、
置中跟隨修復、庫存損益凍結修復、委託排序小修、庫存欄位校準流程。

## 背景:使用者實測回報的問題

1. 置中按鈕想放在表頭(委買/價格/委賣)下面 → 改位置 + 常駐
2. 未武裝不能掛單?→ **是設計,維持現狀**(含閒置 5 分自動解除)
3. 成交張數要顯示在五檔階梯上 → 新顯示格式(見下)
4. 該檔目前倉數要看得到 → 其實已在底部狀態列,但因庫存資料壞掉沒顯示過;加到頂部
5. 按置中後要持續跟隨現價 → 現有實作有 bug(見下)
6. 委託出現昨天的預約單 → **正常**(昨日收盤後掛的預約單屬今日交易日,backlog 重播帶出);只修排序
7. 庫存買賣後不更新 → 最可能是欄位 index 假設錯位,走校準流程
8. 庫存損益不更新 → 前端快照價格凍結 bug

## A. 閃電面板點擊語意改版(核心變更)

### 顯示:掛單與成交分開呈現(模仿券商)

每個價位、每個方向(買/賣)獨立顯示兩個元素:

- **紅方格 `N`** = 我在該價位的未成交掛單張數(Σ actionable 單的 order_qty − filled_qty)。
  有未成交掛單才出現。樣式:紅框方塊,點擊目標做大(撐滿列高),降低誤點。
- **黃括號 `(N)`** = 我今日在該價位的成交張數(Σ **全部**今日單的 filled_qty,含已全成、
  部分成交後刪掉的單)。純顯示、不可點、整日留存。純刪掉沒成交的單不留痕跡。

排列(買側右對齊、賣側鏡像):`[方格] (成交)市場量 | 價格 | 市場量(成交) [方格]`
例:掛 1 張、今日成交 4 張、市場委買 95 → `[1] (4)95  101.5`

成交張數歸屬在**委託價**價位(券商慣例)。市價單(price=null)不上階梯,不變。

### 點擊語意

| 目標 | 行為 |
|---|---|
| 量區空白處 | 加掛 1 筆(qty=張數快捷現值)。**連點=繼續加掛**,不再是即點即刪 |
| 紅方格 | 刪「該價位、該方向」全部活單(沿用既有 cancelAt 逐筆刪) |
| 底部「全部刪單」 | 不變(確認彈窗後逐筆刪) |

同格 500ms 防抖保留(防手抖連發);武裝閘、±5% 可點區、無券鎖買側皆不變。

### 資料來源

全部由現有 `orders` prop(`/api/capital/orders`)推導,**零後端變更**:

- 方格:`actionable && stock_no===selected && price!=null` 按 (price, side) 加總未成交張數
  (= 現有 myLots 邏輯)
- 黃括號:同檔**全部**單(不限 actionable)`filled_qty>0 && price!=null` 按 (price, side)
  加總 filled_qty

`flash-ladder.ts` 的 `LadderRow` 改為 `myBuyLots/mySellLots`(方格)+ `myBuyFills/mySellFills`
(黃括號);聚合抽純函式進 vitest。

## B. 置中按鈕移位 + 跟隨修復

- 「◎ 跟隨置中」按鈕移到表頭「委買 價格 委賣」正下方,**常駐**(目前在階梯下方、
  只有未跟隨才出現)。按下=開啟跟隨(顯示開/關狀態);手動捲動=關閉。
- **Bug 修復**:`scrollIntoView` 程式捲動會觸發容器 `onScroll`,被誤判為手動捲動而立刻
  取消跟隨 → 跟隨模式第一次捲動就自我取消。修法:程式捲動前設 ref 旗標,`onScroll`
  看到旗標只清旗標、不取消跟隨。

## C. 頂部庫存顯示

閃電面板頂部標的列(代號/現價那行)加「庫存 N 張 · 均 X」(`posQty`/均價來自現有
positions prop;無部位不顯示)。底部狀態列「掛單 N 筆 · 部位 +N 張」保留不動。

## D. 庫存資料鏈修復

### D1. 損益凍結 bug(前端,可立即修)

`PositionsList` 的 30 秒報價快照用「已有值就不蓋」(`next[s] ?? row.last_price`)合併,
導致第一次快照價**永遠凍結**,只有恰好訂了 WS tick 的標的會跳。
修法:tick 價與快照價分兩個 map,顯示 `tick ?? snap`;快照每輪覆寫 snap map,
tick 即時蓋 tick map。合併邏輯抽純函式進 vitest。

### D2. 庫存欄位校準(需使用者盤中配合,本批次只定流程)

`capital_balance.py` 的欄位 index 是**未實測的假設表**;「有舊持股但數字不動」症狀
與「現股餘額讀到錯誤欄位(如昨日餘額)」假說一致。後端查詢節奏(成交後 2s debounce
+ 60s 定時)已確認不是問題。

流程:使用者盤中(最好當日有買賣)跑 `python scripts/capital_smoke.py --balance` 抓
`OnRealBalanceReport` 原始字串 → 對照群益 App 持倉校準 index → 真實樣本(去敏)寫進
`test_capital_balance.py` → 修正 `_IDX_*` 常數。**校準前庫存張數/均價不可信。**

## E. 委託列排序小修

排序鍵只有 `HH:MM:SS`,昨日 14:59 掛的預約單會壓在今日早盤單上面。
修法:`capital_reply.py` 解出 idx23 日期(現有真實樣本可驗)→ store 聚合保留 →
排序鍵改 (日期, 時間, 到達序);前端非今日的單在時間前顯示日期(如 `06/10 14:59:48`)。

## 不做的(本批次明確排除)

- 武裝行為改動(使用者確認維持現狀)
- 後端逐筆成交價位明細(成交歸委託價,現有資料即足)
- 本地部位推算(成交回報即時加減張數)— 校準後 2s 重查應夠快,不夠再加
- 5(4) 合併徽章格式(被方格+括號取代)
