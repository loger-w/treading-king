# 造山積木 + 做頭策略族設計 — 2026-06-15

> **本 spec 取代 v1/v2 的「雙峰量價背離造山」設計**(`2026-06-14-peak-divergence-*`)。
> v1/v2 用單一狀態機試圖同時偵測兩座山 + 判定做頭,經回測與逐根 trace 診斷證實有結構性問題:
> pullback_pct 太淺(1%)導致一根 K 線的長上影線就跑完「造山→次峰→觸發」(3362);
> 次峰定義模糊(出量 vs 無量 vs 急拉)導致觸發點與肉眼完全不同(8182 在 11:45 而非 10:43)。
> **根因不是參數、而是架構 — 把「偵測山」跟「判定策略」混在同一個狀態機裡,沒辦法各自做好。**
>
> v3 拆成**積木式架構**:造山是獨立事件偵測器(可複用);策略層消費造山事件,
> 疊加 CDP / 日均等客觀線來觸發。

## 架構:積木式策略

```
造山積木(本次實作)
  │  急拉 + 出量 → 衝高 → N 根沒創新高 → 標記山
  │
  ├─ 策略 A:反彈碰 CDP 無力 → 失望賣壓(未來)
  ├─ 策略 B:無力緩跌 → 跌破 CDP / 日均(未來)
  └─ 未來可擴展:造山 + 外盤比、造山 + 爆量長黑...
```

**造山是前提條件;策略層決定觸發。** 沒有造山的股票,碰 CDP 或破均線只是一般事件;
有造山的才是「主力出完貨、後續走弱」的高置信訊號。

## Part 1:造山積木(本次實作)

### 定義:什麼是一座「山」

急拉出量衝高、然後漲不動了 = 一座山。
主力用量把價格拉上去,之後沒有持續創高 = 攻勢結束、山成形。

### 步驟

#### ① 急拉根偵測(山的起點)

一根結算的 1 分 K 是「急拉根」,當且僅當**同時**滿足:

| 條件 | 參數 | 預設 | 說明 |
|---|---|---|---|
| 陡升 | `surge_pct` | 3.0% | close 相對 `surge_window_bars` 根前的 close 漲幅 ≥ 此% |
| 回看 | `surge_window_bars` | 5 | 跟 surge_pct 合定「多快算急拉」 |
| 出量 | `surge_volume_ratio` | 2.5x | 當根量 ÷ 到當下每分鐘均量 ≥ 此倍 |

- 用 close 不用 high:收在高才是真拉、避開長上影線假突破。
- 5 根 / 3% = 5 分鐘漲 3%,是「主力猛攻」的節奏(6207 主峰 128.5→133 在 5 根內漲 3.5%)。
- 量基準用 `_candle_volume_ratio`(既有 method,到當下每分鐘均量的倍數)。

#### ② 追高(山頂追蹤)

急拉根啟動後,每根持續更新:
- `peak_high`:最高 high(不限急拉根本身 — 急拉根啟動、後續非急拉根繼續創高也追)
- `peak_vr`:期間出現過的最大量比

#### ③ 下山確認(山成形)

**連續 `confirm_bars` 根都沒有再創新高**(high < peak_high)→ 造山完成。

| 參數 | 候選值 | 說明 |
|---|---|---|
| `confirm_bars` | **回測掃 1 / 3 / 5 / 7** | 連續幾根沒創新高才算山成形 |

- 回測用 cache(6207/8064/8150/6239 + 回測篩出的 50 檔)掃四個值,選最佳。
- 選擇標準:6207 在合理時點(09:59 附近)確認造山、雜訊股(8064/8150/6239)也能造山
  但不會在微結構上誤判。
- **不用百分比或 tick 數**:讓市場自己告訴你「山頂到了」,比硬設門檻自然。

#### 輸出

造山完成時標記事件:

```python
{
    "symbol": "6207",
    "peak_high": 134.0,
    "peak_vr": 7.1,
    "peak_minute": <candle.minute>,    # 山頂那根的分鐘
    "confirmed_minute": <candle.minute> # 確認下山的分鐘
}
```

per `(active.id, symbol)` 存在 `_mountain_state`。一天可造多座山;
若新急拉的 high 超過前一座 → 前一座作廢、以新的為準(主力又拉更高)。

### 參數表(造山積木)

| 參數 | 預設 | 用途 |
|---|---|---|
| `surge_pct` | 3.0% | 急拉陡升門檻 |
| `surge_window_bars` | 5 | 急拉回看根數 |
| `surge_volume_ratio` | 2.5x | 急拉出量門檻 |
| `confirm_bars` | 回測定(候選 1/3/5/7) | 連續幾根沒創新高 = 下山 |

### 與現有 code 的關係

- **沿用**:`_candle_volume_ratio`(量基準)、`_update_candle`(candle 結算)、
  `_reset_daily_strategy_state`(跨日清)、`_minutes_since_open`
- **新增**:`_detect_surge`(已在 v2 寫好,簽名/邏輯沿用,改 `surge_pct`/`surge_window_bars` 預設)、
  `_mountain_state` dict(取代 `_peak_state`)、`_update_mountain` method
- **移除**:v2 的 `_eval_peak_divergence`(整個狀態機不再需要;策略層另建)
- **schema**:`PeakDivergenceStrategy` → 改名或新建為積木式 schema(待 spec A/B 定案後設計)

### 回測驗收

用 `_diag_cache.json`(6207/8064/8150/6239)+ `_diag_screen_cache.json`(50 檔):
- 每檔掃 `confirm_bars` = 1/3/5/7
- 輸出:每檔造了幾座山、山頂點位/時間、是否涵蓋肉眼可見的急拉高點
- 6207 應在 09:59 附近(±幾根,取決於 confirm_bars)確認造山、peak_high ≈ 134

### 已知限制

- `_candle_volume_ratio` 有盤中重啟偏誤(day_volume 從 0 重算)— 同 v1/v2。
- 開盤前幾分鐘均量不穩,vr 可能虛高 — 可選加 `min_elapsed_minutes` 但目前先不設。
- 4-tick 近似(1 分 K 拆 4 筆 tick 回測):看門檻命中、不看絕對數。

## Part 2:策略 A — 造山後反彈碰 CDP 無力(未來實作)

> 以下記錄設計方向,待造山積木穩定後再寫詳細 spec + 實作。

### 語意

造山完成(主力已出貨)→ 股價反彈 → 碰到 CDP 壓力線 → 被壓回 → **失望賣壓**。

「同一個碰 CDP 事件,有造過山的股票比沒有的份量重得多。」

### 觸發條件(草案)

1. **前提**:該股票當日有已確認的造山事件
2. **反彈碰線**:價格從山下方往上碰到 CDP 線(由下而上接近)
   - 候選線:CDP-NH、CDP-AH(山後最常見的壓力)
   - 碰線判定:沿用現有 `CdpProximityCondition`(tolerance_ticks + rearm 機制)
3. **被壓回**:碰線後未能站穩、價格回落
   - 可能判定方式:碰線後 N 根 close 仍在線下方 = 壓回確認
   - 或:碰線後回落 ≥ M ticks = 壓回確認
4. **輸出**:推「造山後碰 CDP 壓回」訊號(帶山頂資訊 + 碰的哪條線)

### 與現有基建的關係

- 複用:`CdpProximityCondition`(碰線偵測)、`rearm_ticks`(降噪)、`_field_cache`(CDP 值)
- 新增:「造山狀態」作為碰線的前置條件(filter)

## Part 3:策略 B — 造山後緩跌破 CDP / 日均(未來實作)

> 同上,記錄設計方向,待造山穩定後再展開。

### 語意

造山完成 → 股價無力、緩緩走低 → 跌破 CDP 或日均線 → **趨勢轉弱確認**。

比策略 A 更晚但更確定:A 是「反彈失敗」(偏早、偏積極),B 是「支撐崩潰」(偏晚、偏確認)。

### 觸發條件(草案)

1. **前提**:該股票當日有已確認的造山事件
2. **跌破**:價格由上往下穿越 CDP 或 MA 線
   - 候選線:CDP(中軸)、CDP-NL、SMA5、SMA20
   - 跌破判定:連續 N 根 close 在線下方(沿用 `BreakoutConfirmStrategy` 的 confirm_bars 邏輯)
3. **輸出**:推「造山後跌破」訊號(帶山頂資訊 + 跌破哪條線)

### 與現有基建的關係

- 複用:`BreakoutConfirmStrategy` 的 confirm_bars 判定邏輯、`MAProximityCondition`、`_field_cache`
- 新增:「造山狀態」作為跌破的前置條件

## 設計演進紀錄

| 版本 | 核心邏輯 | 問題 |
|---|---|---|
| v1(PR #33) | 主峰=當日新高,次峰=任意反彈 | 開盤假高觸發、單峰誤抓 |
| v2(本分支 working tree) | 主峰=急拉,次峰=出量(不對稱) | pullback 1% 太淺→微結構觸發;次峰定義模糊 |
| v2.5(討論中棄用) | 雙峰都要急拉(對稱) | 第二峰本質轉弱,要求急拉矛盾 |
| **v3(本 spec)** | **造山=獨立積木;策略層疊 CDP/日均** | 待回測驗證 |

**v3 的核心轉變**:從「一個狀態機做所有事」→「造山偵測 + 策略層各司其職」。
造山只負責「這檔股票被急拉過」;CDP/日均提供客觀的觸發線;組合起來才出訊號。
